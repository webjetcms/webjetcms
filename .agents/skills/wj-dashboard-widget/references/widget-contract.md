# Dashboard widget contract

The framework source is in `src/main/webapp/admin/v9/src/js/dashboard/` (paths in this reference are repository-relative). Read `registry.js`, `dashboard.js`, and `model.js` when extending shared behavior.

For the current catalogue and size variants, inspect registrations in `widgets.js`, `shortcut-widget.js`, `data-widgets.js`, `utility-widgets.js` and `system-widgets.js`, together with backend validation in `src/main/java/sk/iway/iwcm/components/welcome/DashboardSettingsService.java`. `getDashboardDefaults(context)` in `widgets.js` defines the default selection. Keep these sources aligned when adding a variant; historical implementation plans are not an API specification.

## Registration

Import `registerWidget` from `./registry` and register each type once. Definitions contain:

- `type`: stable identifier, also allowlisted with its sizes by the settings backend.
- `titleKey`, optional `descriptionKey`: translation keys ending in `.js`; use the `admin.dashboard` namespace.
- `icon`: a Tabler `ti-*` class.
- `sizes`: subset of `1x1`, `2x2`, `2x3`, `3x2`, `3x3`, `fullauto`; `defaultSize` must belong to it.
- `multiple`, `mandatory`: false by default. Mandatory widgets cannot be removed.
- `defaultOptions`, `defaultDomainOptions`: shared and active-domain preferences, respectively.
- `isAvailable(context)`: presentation eligibility; data authorization remains server-side.
- Optional `isVisible(instance, context)` hides acknowledged content without removing the stored instance. A hidden singleton may expose `reveal(instance, context)` so the catalogue can show it again. Do not use this for permission checks or fixed security/release regions.
- Optional `getTitle(instance, context)` for a text-only instance title.
- Optional `headerLink: {href, labelKey?}` for a safe local module link. `href` is a string or `(instance, context) => string`, allowing a selected record's destination to follow current domain settings. Every update is validated by the shared link helper. Without `labelKey` the title becomes a link; with it a separate translated link sits beside the title. Header navigation survives loading, errors and title updates. Use it instead of a duplicate footer link.
- `render(args)`, optional `configure(args)`.

`render` receives `{container, instance, options, domainOptions, context, signal, refresh, saveOptions}`. Append safe DOM nodes to `container`. `context` contains `data`, `labels`, `config`, `overview`, `dashboard`, `settings`, and `translate(key)`. Use `signal` with asynchronous requests. Return a cleanup function or `{destroy()}` when owning resources; asynchronous returns are supported. The framework aborts and cleans up stale renders, shows failures, and provides retry controls.

`configure` receives the same data context and an abort signal, without refresh/save callbacks. Add labeled controls to its container and return `{read: () => ({options, domainOptions}), destroy?}`. Read may reject invalid input with a localized Error. The framework owns the size picker, modal, save/cancel, focus, and atomic persistence.

Use `saveOptions({options, domainOptions})` for an in-widget preference action. It returns a Promise<boolean>; do not display successful persistence until true. Use `refresh()` to reload only this instance.

`context.dashboard.showAddWidget(type)` opens configuration before a new instance is persisted; canceling leaves the profile unchanged. Use this for the shortcut strip add action.

`context.dashboard.showDialog(title)` opens a shared modal and returns `{body, footer, close, signal, setCleanup}`. Bind requests to its signal and let the shared modal restore focus and dispose resources. Active sessions are managed directly in their fixed list and do not need a separate dialog.

## Settings API

Preferences are embedded as `overviewData.settings` by `DashboardListener` and read by `DashboardController.start()`. There is no settings GET endpoint or fallback fetch. Successful saves and resets update the page data so rebuilding the component retains the confirmed state. A domain change loads new bootstrap data with the page. `PUT /admin/rest/dashboard/settings` saves and returns:

```json
{
  "version": 1,
  "configured": true,
  "shortcutsConfigured": true,
  "legacyBookmarksHandled": false,
  "items": [
    {"id": "security", "type": "sessions", "size": "2x3", "options": {}},
    {"id": "stable-id", "type": "shortcut", "size": "1x1", "options": {"source": "menu", "href": "/apps/form/admin/"}}
  ],
  "domainOptions": {"stable-id": {}},
  "acknowledgedNewsVersion": null
}
```

The server derives user and active domain. Never send a user ID or arbitrary domain selector. The server validates allowed types, sizes, singleton rules, identifiers, and storage limits. Shared layout records and active-domain filters are committed together; failed saves leave the confirmed UI state unchanged.

`getDashboardDefaults(context)` defines the explicit, permission-filtered layout for new and reset profiles: traffic `3x3`, forms/approvals/errors `1x1`, recent pages `3x2`, and referrers/publishing/newsletter `2x2`. Newsletter is the final grid widget. Other registered types, including search terms, top pages and system/activity widgets, remain available in the catalogue and are never appended automatically. On the six-column desktop grid the metric row and recent pages align beside traffic, followed by three equal-width previews. Existing recent-page `2x3`/`3x3`, referrer `2x3`/`3x3`, publishing `2x3`, and search-term `2x3` sizes remain valid; the revised defaults never rewrite saved sizes or order. Sessions, news and search render in fixed regions above the personal grid; shortcuts render as wrapping links directly under the greeting inside the welcome panel, before release news. The section has an accessible label but no visible heading. Fixed-region display does not rewrite stored sizes or order. Widget minimization is not supported: old `collapsed` properties are ignored by both the server DTO and client normalization, without discarding the rest of a saved profile. Default shortcuts select authorized pages/forms destinations, falling back to the first authorized menu destination; no placeholder is created when the menu has no destination. Manually added types use their registered default size. New optional widget types must not rewrite existing personal layouts. Mandatory types are ensured separately.

The controller starts in view mode. The toolbar's feedback button opens `context.overview.showFeedbackModal()` before the widget controls; it remains available independently of widget loading. `setEditing(true)` reveals add-widget, reset, movement and settings controls without persistence. The toolbar order is feedback, add widget, reset, then edit/done. Shortcut add and icon-only edit/done controls remain visible immediately after the links in the wrapping shortcut strip. `setEditingShortcuts(true)` independently reveals a leading grip and a trailing remove button on each shortcut; activating its label opens settings instead of navigating; entering either edit mode closes the other. Shortcuts are absent from the grid catalogue. Shortcut reset is not supported. Removing all shortcuts leaves an intentionally empty section with the add action. Shortcut removal and settings edits offer an eight-second toast undo that restores only the affected instance; a failed save preserves confirmed settings and a failed undo remains retryable. Reset has an explanatory tooltip and uses the standard `WJ.confirm`; the widget catalogue contains no reset control. Successful saves and resets use `WJ.notifySuccess` with a 10-second timeout instead of a persistent inline message. Moving cards stays within the personal grid or shortcut strip; fixed regions cannot be moved. Keyboard/touch movement uses the same region restrictions as drag. Shortcut grips support Space to lift, Left/Right to choose an insertion position, Enter to drop and Escape to cancel without persisting. Clicking the grip retains the position dialog for touch. Pointer and keyboard moves show a raised helper, an original-position dashed placeholder and a white insertion marker across wrapped rows. Shortcut links lose their navigation destination only while editing, and the settings modal includes direct removal. Reflow respects reduced motion. Body-level drag helpers retain the source card's dimensions, background, border and inherited dashboard color tokens.

`DELETE /admin/rest/dashboard/settings` takes no body and resets the authenticated user's shared layout, widget options in **all domains**, and news acknowledgement. It uses the same per-user database lock and transaction as PUT, retains ordered shortcut instances plus `shortcutsConfigured` and `legacyBookmarksHandled` metadata from the locked snapshot, returns a `configured:false` DTO only after commit, and clears the account's admin-settings cache. It preserves every non-dashboard preference and browser-local legacy bookmark. A retained `shortcutsConfigured:true` prevents default shortcut recreation, including for an empty saved section. Older saved layouts without this flag are treated as configured; a missing profile is unconfigured. The system confirmation dialog explains this scope before any DELETE request. A failure uses the normal shared error feedback and leaves the toolbar available for retry. On success the controller applies current defaults; they remain unconfigured until the first personal edit. On failure retain the previous layout, filters, news acknowledgement and removal undo. Never implement reset as a sequence of partial PUT requests or by clearing localStorage.

Shift-clicking the widget reset calls `PUT /admin/rest/dashboard/settings/reset` with a generated settings DTO. The client iterates authorized registry definitions and each definition's `sizes`, assigning unique IDs and default shared/domain options. Shortcuts keep their own section and are preserved from the locked account snapshot; a previously unconfigured shortcut strip may use the supplied defaults. Sessions, news and search remain singletons; all grid types allow repeated instances. The reset transaction replaces all old widget and domain records, clears news acknowledgement, and stores a configured layout before returning it. Failure preserves the previous profile. The generated layout survives reload immediately and supports removal, undo and size changes through normal editing. A normal reset returns to the curated default list. The 48-instance limit fits the current full catalogue and keeps a UUID-based order record within the 2000-character storage limit; reject overflow before any mutation, never truncate.

## Data and rendering

`DashboardListener` embeds `settings`, `notices` and `currentSessions` alongside menu/identity data in the existing `overviewData` JSON. It also embeds `loggedAdmins` (distinct user IDs, names and emails from `SessionHolder` and cached users) only with `welcomeShowLoggedAdmins` permission. Keep Thymeleaf JavaScript inlining in `overview.pug` for safe serialization. These values are supplied with the page; they have no read REST endpoints or client fallbacks. Sessions come directly from `SessionClusterService`. A completed logout removes the session from the supplied list and updates the count; remote logout remains pending until cluster synchronization. Reloading the page obtains fresh session and administrator lists. Browser fixtures for initial data must override the HTML bootstrap with `mockDashboardBootstrap` from `helpers/dashboard-browser.js`; REST mocks remain necessary for writes and independently loaded widget projections.

`DashboardNotices` in `src/main/webapp/admin/v9/src/js/dashboard/notices.js` owns only the system-notice section. Notice data include `id`, `severity`, `icon`, `title`, plain-text `description`, legacy `bodyHtml` and an optional action. All active rows remain visible with text and inline actions; errors cannot be dismissed even if stored preferences contain their IDs.

Notice preferences are separate from the widget profile and survive widget reset. Read `currentUser.adminSettings["dashboard.notices"]` and write `{ label: "dashboard.notices", value: JSON.stringify({ dismissedUntil }) }` through the existing `POST /admin/rest/admin-settings/`. Accept only an HTTP-success response containing boolean `true`; failed saves preserve confirmed state and failed undo remains retryable. `dismissedUntil` maps notice IDs to absolute timestamps seven days ahead for warnings, or zero for hidden information. An expiry timer restores postponed warnings while the page remains open. Ignore obsolete `collapsed` and `errorIds` fields in older stored records without discarding `dismissedUntil`.

Removal animates for 200 ms unless reduced motion is requested. The independent toast appears at the bottom center of the content, confirms the warning's return date and offers undo for eight seconds, pausing on hover or focus. Keyboard removal moves focus to undo; successful undo restores focus to the notice action. Destroy the owner on dashboard disconnection to abort saves and clear expiry, animation and toast work. Behavior tests are in `src/test/webapp/helpers/dashboard-notices.test.js` and `src/test/webapp/tests/admin/dashboard/notices.js`.

The controller shares one `IntersectionObserver` for pending grid renders. It creates card shells immediately, then invokes `render` only when the card intersects the viewport, with no prefetch margin. Requests and chart initialization belong inside these renderers. Entry removes observation; scrolling away and back does not reload an unchanged card. Refresh, configuration changes and domain changes abort previous work and wait for viewport entry again. Removal and destruction also cancel pending waits. Sessions, news, search and shortcuts render immediately; browsers without `IntersectionObserver` retain immediate rendering. Live monitoring and newsletter keep their existing visibility-aware polling after the first render. Browser tests inspecting every card must scroll them into view before waiting for their content; `src/test/webapp/helpers/dashboard-browser.js` provides the shared helpers.

`widget-utils.js` provides safe DOM, URL, field, table, formatting, and fetch helpers. Do not use arbitrary options as HTML or icon classes. Shortcut options are `{source: "menu" | "url", href, title, icon, color}`. Optional `icon` is a single Tabler `ti-*` class (at most 80 characters); an empty or absent value inherits the authorized menu icon or uses `ti-link` for custom URLs. Tabs inherit the nearest parent icon when they have none. Selecting a new destination fills the editable icon field; reopening preserves an override. The field accepts bare names or `ti-*`, previews the result, and persists the normalized class. Optional `color` selects an icon background from `default` (no color), `red`, `peach` (orange), `amber` (yellow), `mint` (green), `cyan` (turquoise), `blue`, `lavender` (purple), or `gray`. Legacy `rose` remains accepted and renders as red. Missing colors keep the neutral icon. Shortcut surfaces always stay neutral; only the icon uses the palette. Yellow and neutral icons use a dark foreground, and the dialog preview matches the link. Palette tokens are shared by the dashboard and its modal. Both options are validated on the server; arbitrary classes and CSS values are rejected. Omitted `source` preserves legacy menu behavior; menu destinations must resolve against the current authorized menu. Explicit URL mode requires a nonempty title and validates a maximum 1024-character root-relative or HTTP(S) URL, rejecting credentials, backslashes, controls and protocol-relative forms. Link titles are always text. `shortcutUrl` mirrors server validation before persistence. The shortcut implementation is in `shortcut-widget.js`. Its shared add/edit dialog uses a labeled combobox over authorized menu entries, with inherited icons, parent breadcrumbs, accent-insensitive matching, deduplicated URLs, arrow/Enter selection and Escape dismissal. Page suggestions reuse `_doc_autocomplete.jsp?editable=true` with debouncing, abort and stale-response protection; results retain the page editor URL as an explicit URL shortcut and use the page title when no override is entered. Keep the custom-URL action visible below the scrollable results. Typing invalidates the old selection; unavailable menu targets require explicit replacement. Icon presets include the current destination icon and a custom name field, whose validity is checked against the loaded Tabler pseudo-element glyph before saving. Colors are labeled circular native radios with selected and focus outlines, shared with the preview on a blue background. Shortcut links are 32 px high and at most 240 px wide; long names use ellipsis and a keyboard-accessible tooltip, shown only when the label actually overflows. Fully visible names have no duplicate tooltip. Unavailable menu links remain focusable with an explanation and editable without navigation. The adjacent add action is 32 px high; edit is 32 × 32 px with a tinted background, no border and an accessible tooltip. During shortcut editing, the same control moves to the right of the welcome heading and shows a check icon with a visible Done label. Disable its tooltip while editing and preserve keyboard focus when moving it back to the shortcut actions. Modal opening hides and disables the invoking tooltip until close. Only destination, source, title and appearance choices are persisted.

Dynamic settings use `WJ.initSelectPicker(root, overrides)` from the same shared initializer called by `app-init.js`. It respects `.no-picker` and `data-live-search`, refreshes existing instances after dependent options change, and keeps dropdowns inside their modal for search focus. Fields use explicit label/input IDs so generated picker buttons are not nested in labels. Dialog cleanup destroys pickers and their detached menus; Escape closes an open picker before closing its modal.

Ranked search-term and top-page previews share the default `3x3` size and header navigation, with no duplicate footer link. The table helper accepts an optional zero-based `numericColumns` array to mark both headers and cells with `md-dashboard-widget__table-number`; keep these columns narrow, right-aligned and unwrapped, reserving room for full text in the remaining columns. Ranked tables use automatic column layout and preserve the compact `2x3` variants. Top-page previews use three columns in both sizes: a shared `pagePreview` link with thumbnail, title and parent path; right-aligned count; and change. Their numeric cells are vertically centered. Recent pages reuse the same preview helper, retaining their editor destinations and date labels; top pages retain the statistics detail destination and period query. The shared statistics TOP API includes `title` and `perexImage` from `StatNewDB.getTopPages`, which reads basic page metadata from `DocDB` without another database query. Both initial cache loading (`getDocForUrls`) and page refresh (`updateInternalCaches`) include `perex_image`, including clearing a removed image. The shared preview helper accepts only local image paths. Missing or failed thumbnails use the decorative file icon.

Reuse existing module REST endpoints; recent pages use `/admin/rest/web-pages/all` with the configured `systemPagesRecentPages` ID, `size=6`, `page=0`, and `sort=dateCreated,desc`. Request only the widget's necessary projection with its abort signal. Every `/admin/rest/` fetch, including GET, must send `X-CSRF-Token: window.csrfToken`: the repository PathFilter enforces this independently of the HTTP method. jQuery's global AJAX setup does not apply to fetch. Return empty states for successful empty results and let actual failures reach the framework. Never convert an access error to a zero count.

The pilot registrations are in `src/main/webapp/admin/v9/src/js/dashboard/widgets.js`: `shortcut` demonstrates authorized menu/custom URL selection, safe links and shared options; `recent-pages` demonstrates `3x2`, `2x3`, and `3x3` previews, the abortable Web pages module endpoint and 38-pixel local perex thumbnails through `/thumb` with `w=76&h=76&ip=6`, lazy loading and a file-icon fallback. Every size retains up to six pages. The labeled, keyboard-focusable list scrolls natively when its content exceeds the available card height. `containNativeScroll(list, signal)` in `widget-utils.js` keeps wheel, touch and navigation-key events from reaching the administration's smooth scrollbar while the list overflows; it preserves native browser behavior and removes its listeners on abort. Sessions and logged administrators use the same helper; the administrator list retains all active names and email actions. Recent pages read the module response's `content` array and render `fullPath`, `perexImage` and the `dateCreated` timestamp directly. Use `fetchJson` so HTTP-200 DataTable errors remain failures. Search previews still retain their localized `saveDate` strings verbatim. Their behavior tests are in `src/test/webapp/helpers/dashboard-widgets.test.js`.

Build request parameters explicitly from allowed fields. Shared `options.days` describes the period; a record selection such as `domainOptions.formName` is domain-specific and takes precedence over any similarly named shared value. If a stored selection is no longer accessible, retain its preference and show an unavailable state; do not silently select the first record or clear the user's selection.

When adding a type, update frontend registration, backend settings validation, translations, relevant data authorization, tests, and this reference where a new reusable pattern is introduced. Add an example link only after the referenced implementation exists.

## Projection examples and errors

Widget data comes from the owning module controllers; there is no `/admin/rest/dashboard/data` controller or fallback. Forms reuse `/admin/rest/forms-list/all`, which returns the complete authorized form list with `formName`, lifetime `count`, and the latest submission date in `createDate`. Sum all counts and sort submitted forms by `createDate` descending in JavaScript before retaining ten distinct form names. The all-forms metric describes lifetime submissions and has no period. This module list is unpaginated; do not mistake its `totalElements` for a submission count or use server sorting to order its enriched dates. Reuse the same list for alphabetically sorted settings choices and selected-form availability. Keep an unavailable saved choice instead of silently replacing it. Authorization and tenant scope follow the existing forms module; do not add a dashboard provider or duplicate its page-access rules.

For a selected form, request `/admin/rest/forms-list/search/findByColumns` with `detail=true`, `formName`, `searchCreateDate=daterange:from-to`, `page=0`, and `sort=createDate,desc`. Request ten rows for a large preview or one for the compact count, and read the full count from `totalElements`. Calculate the inclusive period in calendar days through now; the 7/30/90-day setting is shown only for a selected form. Form periods include today so new submissions are immediately visible; the completed-day rule belongs to analytics widgets. Dates are epoch milliseconds. Do not pass layout IDs or client domain IDs as authorization context or invent unread/processed states.

Approvals fetch the existing `/admin/rest/webpages/toapprove/all` and `/admin/rest/groups/toapprove/all` endpoints with `size=6`, `page=0`, and `sort=saveDate,desc`. Sum `totalElements`, merge by `saveDate`, and retain six entries. Reuse each endpoint's authorization and scope; HTTP 403 and the existing DataTable HTTP-200 errors `Access Denied` / `Access is denied` are permission errors, never empty queues. Reject other nonempty DataTable `error` responses as failures too. The page DataTable response swaps IDs: `historyId` is the page ID and `docId` is the pending history ID. Link directly to `approve.jsp` or `approve_delete.jsp`, including the legacy `[DELETE]` title fallback. Group responses use `GroupSchedulerDetails` and expose `groupId`, `schedulerId`, `isDelete`, `saveDate`, and `userFullName`; link to `web-pages-list/?groupid=...&scheduleId=...`, adding `&act=delete` for deletions, as in approval emails. Prepend the shared `ti-file-text` icon for pages and `ti-folder` for folders. Each item opens a new window with `target="_blank"` and `rel="noopener"`. The header and count retain the complete approval list. For folder-only deep links, defer the folder-tab click until the shared subtab handler has updated its IDs.

Traffic calls `/admin/rest/stat/views/search/findByColumns` once for the current and previous completed periods, with `statType=days` and a bounded `size=2*days`. Map `dayDate` and the selected `visits`, `sessions`, or `uniqueUsers` metric into `series` and `previousSeries`. Summaries add the daily values, like the statistics module; label unique users explicitly as the sum of daily unique visitors. Previous points retain their real dates and align by index for chart comparison. TOP pages call `/admin/rest/stat/top/search/findByColumns` for the current and previous ranking. This module caps each response at 100 rows even when `size=6` is requested; retain only the first six current rows for the widget. Compare by `docId`, preserve titles/images and link to statistics details with the current `dateRange`. Missing previous rows remain unavailable, never zero. Both endpoints use `searchDayDate=daterange:from-to`, `searchFilterBotsOut=true`, `pagination=true`, and `searchRootDir` from the server-injected `overviewData.statRootGroupId`. The module applies its folder permission rules. Do not query an unavailable root as all domains. Build completed periods with calendar dates to preserve daylight-saving transitions. Neither widget has a dashboard data provider or fallback. A zero comparison baseline has no percentage growth.

Search terms reuse `/admin/rest/stat/search-engines/search/findByColumns` with `searchWebPage=-1` and an empty `searchEngine`, mapping `queryName` and `queryCount`. Referrers reuse `/admin/rest/stat/referer/search/findByColumns` with `searchChartType=not_chart`, mapping `serverName`, `visits`, and the supplied `percentage`. Both use the same completed periods and authorized root filter as traffic, with one request and six preview rows. The module returns rankings capped at 100 rows; its percentages describe that ranking, not just the visible preview.

Errors reuse `/admin/rest/stat/error/search/findByColumns` with `searchFilterBotsOut=false`, empty `searchurl`, `size=6`, `page=0`, and `sort=count,desc`. Read the main count from `summary.count`, never from the six returned rows. Map each weekly row's `url` and `count` directly. Expand the selected period to calendar weeks, cap its end at now, and retain the weekly-total label. Permissions, tenant scope, grouping and historical-data limits follow the existing error module; it has no folder filter. These three widgets have no dashboard providers or SQL fallbacks.

Charts use `src/main/webapp/admin/v9/src/js/dashboard/charts.js`: create a uniquely identified host with `chartHost`, then call `mountChart` with the render signal and a factory for `ChartTools.LineChartForm` or `BarChartForm`. The helper loads the existing bundle with `window.initAmcharts()`, creates the chart through `ChartTools.createAmchart`, and returns paired `ChartTools.destroyChart` cleanup. Pass that cleanup back from the widget renderer. Do not reuse a host ID across asynchronous renders or keep an AmCharts root after abort. `data-widgets.js` demonstrates equal-period lines with real dates retained in tooltips and period labels in the legend. Traffic and referrers keep their precise-value tables visually hidden for screen readers, without a visible data disclosure. Referrers use horizontal AmCharts percentage tracks on a fixed 0–100 scale with each literal source label and percentage above its track; counts remain available in tooltips and the equivalent table. Shares use the module's supplied percentages, without recomputing them from the displayed preview. The `2x2` preview shows three sources, larger variants five or six. It does not invent search/direct categories from the recorded source domains. Dashboard previews omit the full-report scrollbars and zoom controls; the existing WebJET theme and locale remain shared with other modules. `charts.js` reads `--wj-dashboard-chart-primary`, `--wj-dashboard-chart-comparison`, `--wj-dashboard-chart-grid` and `--wj-dashboard-chart-label` from the chart host at creation. Define their colors as SASS tokens exported to CSS custom properties, without hard-coded JavaScript palettes.

Publishing calls `/admin/rest/web-pages/history/all?auditVersion=true`, reusing the audit module's complete cached schedule. Map `publicable` with `publishStartDate` to publication events and `disableAfterEnd` with `publishEndDate` to expiration events. Keep future events, deduplicate by page/kind/date, sort by event date, and retain six entries. There is no upper date bound. Compact `2x2` cards show two events and the legacy `2x3` variant five, with action labels distinguishing publication from expiry. Dates include the year when it differs from the current year. Require both `menuWebpages` and `cmp_adminlog` for widget availability. The header opens `/admin/v9/apps/audit-awaiting-publish-webpages/`; individual events link to their page. Scope and authorization follow the existing audit module, without a dashboard provider or SQL fallback.

Newsletter requests `/admin/rest/dmail/campaings/all?size=14&page=0&sort=id%2Cdesc` and displays the latest campaign by default. Map `subject`, `countOfSentMails`, `countOfRecipients`, and the already localized `editorFields.status`; omit failure/open/click statistics absent from this API. The configuration offers these recent campaigns. An older saved `campaignId` is loaded through the module’s `/{id}` endpoint with its existing domain authorization and remains first in the preview. A failed saved selection remains an error. Up to three campaigns appear in the large card. Only a visible active campaign whose `sendAt` is not in the future polls every 30 seconds; compare its status with the module’s active label embedded in the Thymeleaf page. Do not infer delivery states from incomplete counts or add newsletter SQL to the dashboard.

`fetchJson` converts JSON `reason` into `error.dashboardReason`, which the shell translates, and rejects module DataTable errors as failures. A saved form absent from the authorized list raises `selection-unavailable`. `domain-unavailable` covers a missing active-domain root for statistics requests. Do not catch provider errors and return an empty array or zero.

`utility-widgets.js` demonstrates mandatory session management, version-specific announcement acknowledgement, and explicit search scope. Session removal must inspect the endpoint's `success` result as well as HTTP status; a 200 response can still report failure. A successful response with `pending: true` means the verified remote session is awaiting cluster synchronization; show that state instead of claiming immediate logout. The current session remains first in the compact preview and cannot be removed through this endpoint. Its fixed header region shows the localized "My active sessions" title and a non-interactive count badge. The list retains every active session and direct logout controls, including profiles with a previously collapsed session widget. A bounded scroll area in this security region preserves access to longer session lists.

Release announcements arrive through WebJET's Markdown renderer, which may represent paragraph boundaries as `<br><br>`. Preserve its complete HTML in the expanded release, including all paragraphs and formatting; extract plain text only for the release version and collapsed teaser. The labeled collapse control shares a footer with the complete changelog link. Acknowledgment of its version collapses it to a visible one-line summary and a more-info toggle, rather than hiding the release. An updated version expands again. Preserve the last confirmed presentation if acknowledgment fails.

The large forms card retains all ten preview rows in a labeled, keyboard-focusable native scroll area, using `containNativeScroll` with abort cleanup. On mobile the list is capped at 320 pixels. For a selected form with submissions, load `/admin/rest/forms-list/columns/{formName}` for field labels and column order; multistep field IDs alone do not identify contact fields. Prefer populated name, surname and email fields, ignoring case, accents, separators and parenthesized step labels. Otherwise display the first three populated columns in definition order. Render values as text and link each row to `/apps/form/admin/detail/?formName=...&id=...`. Compact cards, all-form previews and empty results need no column metadata. Propagate module failures through the shared error handling.

## System and activity widgets

`system-widgets.js` registers `changed-pages`, `audit`, `logged-admins`, `server-memory`, and `server-cpu`. They replace the removed legacy overview; shortcuts replace the old browser-local bookmark UI. The legacy `{name, path}` array is stored under `localStorage["bookmarks"]`, so no database migration is needed. After successfully loading the profile, the controller automatically imports a nonempty legacy array once into the signed-in account. It replaces only shortcut instances, preserving safe URLs (including query strings and fragments), names and order while deduplicating URLs. Other widgets, domain filters and news acknowledgement remain unchanged. Only a successful server save records `legacyBookmarksHandled`; the legacy key is then removed if its raw value has not changed during the request. Invalid records, save failures and capacity limits retain both original bookmarks and current preferences without a partial import; loading again retries. Missing or empty legacy lists leave defaults intact. The account marker prevents another overwrite even if localStorage cleanup is unavailable or another browser has old bookmarks. These widget types are optional and support multiple instances and existing personal grid layouts remain unchanged.

Changed pages call `/admin/rest/web-pages/all?auditVersion=true&size=6&page=0&sort=dateCreated%2Cdesc`, mapping `title`, `fullPath`, `perexImage`, `authorName`, `dateCreated`, and `docId` into the activity preview. ## Persistence and verification

`DashboardSettingsService` validates the schema and `DashboardSettingsRepository` writes the existing `user_settings_admin` table atomically. The MariaDB/MySQL table must use InnoDB; the targeted migration is in `src/main/webapp/WEB-INF/sql/autoupdate-webjet9.xml`. Do not bypass the repository guard or introduce a separate preference store. The REST DTO uses ordinary maps/lists, compatible with the application's Jackson 3 response converter.

The shared records are `overview.layout.v1`, `overview.widget.<id>`, and `overview.news`; domain records are `overview.domain.<rootGroupId>.<id>`. Immediate removal undo retains the removed instance's other-domain selections until the next successful edit. A failed save must retain the undo opportunity. Unavailable widget types remain in the stored profile.

Run the frontend framework and widget behavior tests (`src/test/webapp/helpers/dashboard-*.test.js`), relevant `Dashboard*Test` Java tests, and the Codecept scenarios in `src/test/webapp/tests/admin/dashboard/widgets.js`, `src/test/webapp/tests/admin/dashboard/data.js`, and `src/test/webapp/tests/admin/dashboard/catalogue.js`. Test security operations only against sessions created by the test. Never invoke the feedback email scenario as part of a dashboard smoke test.

The real reset scenario in `src/test/webapp/tests/admin/dashboard/reset.js` creates and removes a disposable account. The catalogue tests inspect AmCharts root registration after refresh, size change, removal, and undo; browser assertions also check chart canvas rendering and the table equivalent.
