# Stav návrhu a realizácie

## Zjednotenie persistence 12. novembra 2026

`BranchRestController` spája správu DataTable, zoznam prepínača, výber kontextu a náhľad. Samostatný `BranchDatatableRestController` bol odstránený. DataTable správa používa štandardné `getOneItem`, `insertItem` a `editItem` rodičovského `DatatableRestControllerV2`. Odstránené sú vlastné CRUD metódy, duplicitná doménová/CSRF kontrola, `checkItemPerms`, `updateMetadata` aj jeho zámkový query. `beforeSave` nastavuje počiatočný stav, autora a časy; názov validujú anotácie a farba má iba limit dĺžky DB stĺpca. Doménu spravuje `DomainIdRepository` a štandardný Editor. Audit poskytuje `AuditEntityListener`.

Po opätovnom posúdení používateľ schválil odstránenie `COLOR_PATTERN` aj príznakov `insertable=false` a `updatable=false` z entity. Metadáta sa upravujú štandardným DataTable merge s `hiddenEditor`; nové vetvy dostanú v `beforeSave` počiatočný stav bez plánovania a priebehu publikovania. Osobitná ochrana proti uloženiu názvu tej istej vetvy presne počas publikačného prechodu sa nepožaduje. Kontroly stavu a revízie pri samotnom publikovaní zostávajú zachované.

Vytváranie používa výlučne DataTable Editor. Odstránené sú pôvodný `POST /admin/rest/branches`, DTO `Create`, duplicitné metódy `BranchService.create` aj ich vlastná výnimka. Spoločný `BranchRestController` poskytuje aj zoznam prepínača, výber kontextu a URL náhľadu. Príprava fixture dát je iba v testovom `BranchJpaTest`.

`BranchService` používa Spring Data JPA na metadátové čítanie a publikačné prechody. Transakčná anotácia na celej službe bola odstránená; aktualizačné metódy repository majú vlastné transakcie. DataTable používa spoločný základ `/admin/rest/branches`; štandardný `/{id}` vracia metadáta a porovnanie používa existujúce `/{id}/progress`. HTTP chyby výberu kontextu a náhľadu si zachovávajú pôvodné statusy aj v kontroléri označenom `@Datatable`. JPA sa používa aj na určenie domény náhľadu, výber splatných balíkov, podmienené zastavenie scheduleru, dokončenie/chybu publishera, čítanie médií/kategórií a súborovú identitu binárneho porovnania.

Natívne JDBC zostáva v rezervácii produkčných ID, WORK/LIVE zápisoch so spoločnou transakciou a checkpointmi, účinných SQL reláciách a fyzickej kontrole DB schémy/oprávnení. Nezávislé JPA volanie sa nevkladá doprostred týchto zápisových transakcií. Verejné rozhranie správcu ani schéma sa nemenia.

Overenie po zlúčení kontrolérov a odstránení transakcie zo služby: **148 úspešných unikátnych Java testov / 0 zostávajúcich chýb / 16 zámerných skipov** s `WEBJET_P02_DB` až `WEBJET_P07_DB=true`. Hlavný beh mal 164 testov, z toho 146 PASS a dva nové MVC testy zlyhali pre chýbajúci JSONPath. Po nahradení asercií existujúcim JSON parserom prešla finálna sada `BranchRestControllerTest` **11/11 PASS**, vrátane oboch nových prípadov. Testy bežia nad skutočnými Spring repository a transakciami v izolovanej MariaDB `127.0.0.1:33316/webjet_p01`. Overené sú zdedené DataTable vytvorenie a úprava, anotácie validácie, uloženie farby mimo palety UI, serverová doména/autor/časy, inicializácia publikačných údajov pri vytvorení a jeden CREATE/UPDATE audit cez listener. Test publikačných polí overuje bežný JPA zápis a následný podmienený prechod publishera. Zahrnuté sú aj binárne BASE/LIVE/WORK verzie, náhľad, médiá a cron. Test umelo načasovaného súbehu s premenovaním bol odstránený podľa schváleného rozsahu.

Java sada zahŕňa aj JSON serializáciu novej entity bez `domainId` z `GET /-1`, doménový zoznam prepínača, registráciu DataTable a publikačných endpointov bez kolízií, zachovanie HTTP 409 pri nesúlade domény a odmietnutie pôvodného `POST /admin/rest/branches` stavom `405 Method Not Allowed`. Frontend production build prešiel s dvomi existujúcimi upozorneniami na veľkosť balíkov. Po reštarte aplikácie so zlúčeným `BranchRestController` prešiel CodeceptJS scenár `branch-management.js` **1/1 PASS**: vytvorenie, validácia, úprava názvu/farby/poznámky, porovnanie, otvorenie webu a kontrola oprávnení. V serverovom logu sa neobjavila chyba serializácie novej entity.
