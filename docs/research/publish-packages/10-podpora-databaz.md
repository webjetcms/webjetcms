# Podpora databáz pre publikačné balíky

Pre prvé vydanie by som overil **MariaDB 10.11 LTS s InnoDB**. Ak má vydanie podporovať aj druhý databázový systém, zvolil by som **PostgreSQL 16**. MySQL 8.4 má k balíkom bližší dialekt, ale štandardná inštalácia aj bežné načítanie priečinkov narážajú na rezervované slovo `GROUPS`. Poradie by som zmenil, keby pre cieľovú inštaláciu prešiel základný test aktualizácie, administrácie a LIVE na skutočnom MySQL 8.4. [SQL kľúčové slová MySQL](https://dev.mysql.com/doc/refman/8.4/en/keywords.html), [inštalačná schéma](../../../src/main/webapp/WEB-INF/sql/blank_web.sql#L535), [načítanie priečinkov](../../../src/main/java/sk/iway/iwcm/doc/GroupsDB.java#L224).

## Verzie a odhad práce

Odhady sú v pracovných dňoch pre jedného vývojára po sprístupnení testovacej databázy. Zahŕňajú implementáciu a overenie balíkov vrátane aktualizácie schémy. Prípadné širšie opravy jadra MySQL a konverzie zákazníckych tabuliek sa odhadujú samostatne. Predpokladom je jedna inštancia WebJETu, jedna zapisovateľná DB a lokálne súborové úložisko, rovnako ako v POC. Stav vychádza z kódu na `6711db48a7`, dokumentácie výrobcov a cieleného JDBC overenia MariaDB 10.11 a 11.4. [Inštalačné minimum CMS](../../sk/install/setup/README.md#základné-požiadavky-na-server), [overený profil POC](../../sk/admin/setup/publishing-packages.md#inventár-a-hranice).

## Spoločná práca

1. **Schéma a cron.** Päť tabuliek aj registrácia `BranchScheduler` sú dnes iba vo vetve `<mysql>`. Tá sa používa pre MySQL aj MariaDB. PostgreSQL, SQL Server a Oracle potrebujú vlastné DDL s porovnateľnými typmi, indexmi, unikátnymi kľúčmi a kaskádovým zmazaním. Ak už inštalácia spustila tento PR, migrátor si mohol zapísať úspech aj pri prázdnom SQL pre jej dialekt. Pre také inštalácie treba použiť nové identifikátory migrácií alebo výslovne vyriešiť ich opakované vykonanie. [Schéma balíkov](../../../src/main/webapp/WEB-INF/sql/autoupdate-webjet9.xml#L4444), [registrácia plánovača](../../../src/main/webapp/WEB-INF/sql/autoupdate-webjet9.xml#L4713), [výber dialektu migrácie](../../../src/main/java/sk/iway/iwcm/system/UpdateDatabase.java#L474), [zápis úspechu](../../../src/main/java/sk/iway/iwcm/system/UpdateDatabase.java#L644).
2. **Aktivácia a JDBC.** `BranchReadiness` vyžaduje podporovaný rad MariaDB, kontroluje InnoDB a číta schému cez `information_schema` a `DATABASE()`. Pre ďalšie servery treba overiť aktuálnu schému, fyzické typy, oprávnenia a izoláciu JDBC aj priameho JPA spojenia. Čítanie a zápis podľa typu stĺpca má zachovať dlhý text, `NULL`, dátumy a číselné navigačné voľby. Rovnaká uložená hodnota musí mať po opätovnom načítaní rovnakú reprezentáciu pre porovnanie a kontrolný hash. Zdieľať sa dajú existujúce pomocné metódy pre booleovské výrazy a zoznamy `IN`, ako aj stránkovacie vzory z `NewsQuery`. [Aktivácia](../../../src/main/java/sk/iway/iwcm/branch/BranchReadiness.java#L33), [čítanie JDBC](../../../src/main/java/sk/iway/iwcm/branch/BranchStore.java#L261), [normalizácia hodnôt](../../../src/main/java/sk/iway/iwcm/branch/BranchSnapshot.java#L76), [pomocné SQL metódy](../../../src/main/java/sk/iway/iwcm/DB.java#L1220), [stránkovanie Noviniek](../../../src/main/java/sk/iway/iwcm/components/news/NewsQuery.java#L111).
3. **Rezervácia ID a bezpečné publikovanie.** Stránka alebo priečinok dostane konečné ID už v balíku. MariaDB ho rezervuje technickým insertom a následným zmazaním v jednej transakcii. PostgreSQL a Oracle môžu rezervovať z existujúcej sekvencie LIVE. Médiá už používajú spoločný `PkeyGenerator`, ktorý má atómový zápis pre všetky štyri dialekty. Pri publikovaní musia zmena LIVE, príslušná história a kontrolný bod položky spolu prejsť commitom alebo rollbackom. Opakovanie po chybe musí rozpoznať stav po commite vrátane následnej aktualizácie vyhľadávania, Lucene a súborov. [Rezervácia ID](../../../src/main/java/sk/iway/iwcm/branch/BranchStore.java#L186), [generátor médií](../../../src/main/java/sk/iway/iwcm/PkeyGenerator.java#L265), [transakcia položky](../../../src/main/java/sk/iway/iwcm/branch/BranchPublishService.java#L126), [obnova vyhľadávania](../../../src/main/java/sk/iway/iwcm/branch/BranchPublishService.java#L346).

## Rozdiely podľa servera

### MariaDB 10.11 a MySQL 8.4

Oba servery môžu zdieľať DDL balíkov, `AUTO_INCREMENT`, priame vloženie rezervovaného ID, `FOR UPDATE`, `LIMIT` a rekurzívny strom. MariaDB má perzistentný InnoDB čítač od 10.2.4 a MySQL 8.4 tiež dokumentuje, že rollback raz pridelené ID nevráti. Na najstaršom vybranom rade treba overiť presný rekurzívny dotaz, `utf8mb4` index na virtuálnej ceste a ovládač MariaDB Connector/J 3.5.10. Pri MySQL treba overiť predvolený striktný SQL režim, kolácie a radenie náhľadu. [MariaDB AUTO_INCREMENT](https://mariadb.com/docs/server/server-usage/storage-engines/innodb/auto_increment-handling-in-innodb), [MySQL AUTO_INCREMENT](https://dev.mysql.com/doc/refman/8.4/en/innodb-auto-increment-handling.html), [MySQL rekurzívne CTE](https://dev.mysql.com/doc/refman/8.4/en/with.html), [MySQL SQL režimy](https://dev.mysql.com/doc/refman/8.4/en/sql-mode.html), [MariaDB Connector/J](https://mariadb.com/docs/connectors/mariadb-connector-j/about-mariadb-connector-j).

Podmienkou aktivácie zostáva InnoDB pre päť pracovných a šesť dotknutých LIVE tabuliek. Staršie MyISAM inštalácie potrebujú plánovanú konverziu podľa skutočných úložných enginov. Pri `documents` treba preveriť spoločný FULLTEXT index na `(title, data_asc)` a výsledky vyhľadávania po zmene. `pkey_generator` prideľuje rozsahy samostatne a môže zostať MyISAM. [Konverzia v správcovskej príručke](../../sk/admin/setup/publishing-packages.md#konverzia-existujúcich-tabuliek-na-innodb), [obmedzenia MySQL FULLTEXT](https://dev.mysql.com/doc/refman/8.4/en/fulltext-restrictions.html).

Pre MySQL je prvá brána **bežný WebJET s vypnutými balíkmi**. `UpdateDatabase` posiela čistú schému do JDBC bez úpravy `CREATE TABLE groups`. `GroupsDB` posiela bez úvodzoviek aj bežný `SELECT ... FROM groups` a podobné zápisy. Overiť treba bootstrap aj aktualizáciu existujúcej schémy a bežnú správu priečinkov. Súčasný CI job používa obraz MariaDB aj pri URL s prefixom `jdbc:mysql:`. [Bootstrap](../../../src/main/java/sk/iway/iwcm/system/UpdateDatabase.java#L1373), [načítanie priečinkov](../../../src/main/java/sk/iway/iwcm/doc/GroupsDB.java#L224), [CI databáza](../../../.github/workflows/gradle.yml#L32), [MySQL GROUPS](https://dev.mysql.com/doc/refman/8.4/en/keywords.html).

### MariaDB 10.11 LTS a 11.4 LTS

**Oba rady zvládli rovnaké schémy a SQL cez Connector/J 3.5.10.** Na izolovaných serveroch **10.11.19** a **11.4.13** som importoval referenčnú schému z CI a dvakrát aplikoval SQL migrácií balíkov. Vzniklo päť InnoDB tabuliek s `utf8mb4_bin` a jediná úloha cronu. Presný rekurzívny dotaz PR vrátil potomkov aj potrebných LIVE predkov spracovávanej stránky bez duplicít. Plná projekcia náhľadu cez `UNION ALL` zvládla filtrovanie, stránkovanie, dvojité použitie zdroja v dotaze s atribútmi, dlhé HTML s Unicode a číselný príznak `-1`. [Referenčná schéma](../../../.github/workflows/blank_web_autotest.sql), [SQL migrácií](../../../src/main/webapp/WEB-INF/sql/autoupdate-webjet9.xml#L4448), [rekurzívny dotaz](../../../src/main/java/sk/iway/iwcm/branch/BranchView.java#L82), [projekcia náhľadu](../../../src/main/java/sk/iway/iwcm/branch/BranchSql.java#L21).

Na oboch serveroch Connector/J nastavil `READ_COMMITTED`. Druhé spojenie nevidelo technické INSERTy pri rezervácii ID stránky a priečinka. Po rollbacku bežný insert dostal vyššie ID a rezervované ID sa dalo vložiť explicitne. Prešiel samostatný zápis rozsahu ID médií cez `LAST_INSERT_ID`, čakanie konkurenčného zápisu na zámok a test, že LIVE zápis, história a publikačný kontrolný bod sa spoločne vrátia späť alebo sa potvrdia. Po potvrdení SQL FULLTEXT našiel nový text. Na referenčnej schéme som pred skúškou inicializoval záznam generátora `media`, ktorý vyžaduje aktivácia na oboch radoch. [Rezervácia ID](../../../src/main/java/sk/iway/iwcm/branch/BranchStore.java#L186), [kontrola generátora](../../../src/main/java/sk/iway/iwcm/branch/BranchReadiness.java#L65), [perzistencia AUTO_INCREMENT](https://mariadb.com/docs/server/server-usage/storage-engines/innodb/auto_increment-handling-in-innodb).

Na oboch serveroch prešla aj konverzia referenčných kópií všetkých šiestich LIVE tabuliek z MyISAM na InnoDB. Spoločný index `FULLTEXT(title, data_asc)` po konverzii vrátil testovaciu stránku. Pri zákazníckych inštaláciách rozsah a trvanie konverzie závisia od stavu a veľkosti tabuliek. [Postup konverzie](../../sk/admin/setup/publishing-packages.md#konverzia-existujúcich-tabuliek-na-innodb).

**Rozdiely sú hlavne v prevádzke.** Na použitých obrazoch malo 10.11 serverovú koláciu `utf8mb4_general_ci` a 11.4 `utf8mb4_uca1400_ai_ci`. Pracovné tabuľky ju majú deklarovanú explicitne, pri zákazníckych LIVE tabuľkách záleží na ich vlastných koláciách. Model nákladov optimalizátora sa v rade 11.x zmenil, preto sa oplatí porovnať plán a čas rekurzie a Noviniek pri väčšom balíku. Obe skúšané inštancie mali `innodb_snapshot_isolation=OFF`, formát `DYNAMIC` a 16 KiB stránky. Šírka indexu `(branch_id, virtual_path)` môže byť problém pri neštandardnom formáte `COMPACT` alebo 4 KiB InnoDB stránkach v ktoromkoľvek rade. [Zmeny pri prechode na 11.4](https://mariadb.com/docs/server/server-management/install-and-upgrade-mariadb/upgrading/mariadb-community-server-upgrade-paths/upgrading-from-mariadb-10-11-to-mariadb-11-4), [formát a limity InnoDB](https://mariadb.com/docs/server/server-usage/storage-engines/innodb/innodb-row-formats/innodb-dynamic-row-format).

**Rozsah zmeny pre vydanie.** Povoľovanie konkrétnych overených radov je v `BranchReadiness`. Oba rady používajú rovnakú schému, SQL aj ovládač. Opravné vydania dostupné podľa výrobcu k 24. 11. 2026 sú 10.11.20 a 11.4.14. Test použil predchádzajúce opravné vydania dostupné v registri. Komunitná údržba trvá pre 10.11 do februára 2028 a pre 11.4 do mája 2029. [Kontrola verzie](../../../src/main/java/sk/iway/iwcm/branch/BranchReadiness.java#L33), [aktuálne opravné vydania a údržba](https://mariadb.org/mariadb-server-12-3-11-8-11-4-and-10-11-q4-2026-maintenance-releases/).

### PostgreSQL 16

Môže zachovať rekurzívne `WITH RECURSIVE … UNION`, `LIMIT/OFFSET` a `FOR UPDATE`. Pre LIVE stránky a priečinky použiť `nextval` nad sekvenciou priradenou v skutočnej schéme, napríklad cez `pg_get_serial_sequence`. Nové tabuľky môžu použiť identitu a `text` pre HTML a serializované snapshoty. Overiť treba, ako EclipseLink mapuje anotované `@Lob` polia pri zvolenom DDL. [Schéma PostgreSQL vo WebJETe](../../../src/main/webapp/WEB-INF/sql/blank_web_pgsql.sql#L1032), [sekvencie](https://www.postgresql.org/docs/16/functions-sequence.html), [výber priradenej sekvencie](https://www.postgresql.org/docs/16/functions-info.html#FUNCTIONS-INFO-SCHEMA), [rekurzívne dotazy](https://www.postgresql.org/docs/16/queries-with.html#QUERIES-WITH-RECURSIVE), [SELECT a zámky](https://www.postgresql.org/docs/16/sql-select.html).

Hlavné riziko je typovanie. Pracovný `UNION ALL SELECT ?` musí zostať typovo zhodný s LIVE stĺpcami aj pri `NULL` a pri projekciách odvodených stránok. Pri stránkach sú navigačné príznaky booleovské, pri priečinkoch niektoré zodpovedajú číselným voľbám. Rozlíšenie treba zachovať medzi JDBC, DDL, filtrami a hashom. PostgreSQL má tiež odlišné predvolené radenie `NULL` od MariaDB/MySQL. Test náhľadu má porovnať výsledky s LIVE na tej istej databáze, vrátane filtrov, počtu a stránkovania. [Typy pri `UNION`](https://www.postgresql.org/docs/16/typeconv-union-case.html), [radenie](https://www.postgresql.org/docs/16/queries-order.html), [projekcia náhľadu](../../../src/main/java/sk/iway/iwcm/branch/BranchSql.java#L21), [klasifikácia príznakov](../../../src/main/java/sk/iway/iwcm/branch/BranchFields.java#L108).

### Microsoft SQL Server 2022

- LIVE stránky a priečinky používajú `IDENTITY`. Po rezervácii bude explicitný insert pri publikovaní vyžadovať `SET IDENTITY_INSERT ... ON/OFF` na tom istom spojení. Príkaz vyžaduje vlastníctvo tabuľky alebo `ALTER`. Po chybe pri vypnutí treba fyzické spojenie vyradiť z poolu. Upraviť treba aj aktivačný probe `INSERT ... SELECT *`, ktorý by zahŕňal stĺpec identity. [LIVE tabuľky](../../../src/main/webapp/WEB-INF/sql/blank_web_mssql.sql#L151), [IDENTITY_INSERT](https://learn.microsoft.com/en-us/sql/t-sql/statements/set-identity-insert-transact-sql), [probe práv](../../../src/main/java/sk/iway/iwcm/branch/BranchReadiness.java#L132).
- Treba nahradiť `FOR UPDATE` vhodnými zámkami pre konkrétny dotaz a otestovať súbeh s LIVE editáciou. Rekurzia vyžaduje `UNION ALL` medzi kotvou a rekurzívnou časťou, kontrolu cyklov, deduplikáciu a rozhodnutie o hĺbke nad predvolených 100. Existujúce `ntext` polia treba čítať a projektovať ako `nvarchar(max)` tam, kde ich dotaz potrebuje. Overiť treba existujúci ovládač jTDS aj správanie pri Unicode, dlhom HTML a chybách spojenia. [Zámky SQL Servera](https://learn.microsoft.com/en-us/sql/relational-databases/sql-server-transaction-locking-and-row-versioning-guide), [rekurzívne CTE](https://learn.microsoft.com/en-us/sql/t-sql/queries/with-common-table-expression-transact-sql), [typy `ntext` a `nvarchar(max)`](https://learn.microsoft.com/en-us/sql/t-sql/data-types/ntext-text-and-image-transact-sql), [ovládače projektu](../../../build.gradle#L207).
- Plná projekcia používa **77 parametrov na jednu pracovnú stránku**. Pri Novinkách s atribútovým filtrom sa zdroj binduje dvakrát. Už 14 plne projektovaných zmien znamená 2 156 parametrov ešte pred ďalšími filtrami. SQL Server má hranicu približne 2 100 pre tento spôsob odovzdávania parametrov. Pred podporou treba prakticky overiť hranicu s použitým ovládačom a zmeniť zdroj na dotaz nad množinami riadkov v DB, napríklad spojením pracovných a LIVE tabuliek, so zachovaním odvodených stránok, výberu verzie a stránkovania. [Stĺpce dokumentu](../../../src/main/java/sk/iway/iwcm/branch/BranchFields.java#L119), [parametre Noviniek](../../../src/main/java/sk/iway/iwcm/components/news/NewsQuery.java#L361), [parametre SQL Servera](https://learn.microsoft.com/en-us/sql/connect/jdbc/using-table-valued-parameters).

### Oracle 19c

- Rezervácia LIVE ID môže čerpať z `S_documents` a `S_groups`. Triggery v štandardnej schéme prideľujú číslo iba pri `NULL` ID. Samotné JDBC `RETURN_GENERATED_KEYS` bez určenia stĺpca môže vrátiť `ROWID`. Pre JPA identitu v nových tabuľkách treba overiť zvolený Oracle JDBC profil s Java 17 a EclipseLink. Staršie typy LIVE stĺpcov zostanú relevantné aj na novom serveri. [Sekvencia a trigger](../../../src/main/webapp/WEB-INF/sql/blank_web_oracle.sql#L433), [vracanie kľúčov v JDBC](https://docs.oracle.com/en/database/oracle/oracle-database/19/jjdbc/JDBC-standards-support.html), [ovládače Oracle](https://www.oracle.com/database/technologies/appdev/jdbc-downloads.html).
- Najviac práce vyžaduje kombinácia `CLOB`, číselných príznakov, názvov stĺpcov v metadátach, dátumov a interpretácie prázdneho reťazca ako `NULL` v znakových poliach. Napríklad `awaiting_approve <> ''` má na Oracle inú sémantiku. Pre 19c treba doplniť `FROM DUAL` pre literálové ramená alebo zmeniť projekciu. Príručka Oracle pre LOB povoľuje `UNION ALL`, takže treba otestovať správne typované `CLOB` aj pri dlhom HTML a konkrétnych filtroch. [Oracle schéma](../../../src/main/webapp/WEB-INF/sql/blank_web_oracle.sql#L340), [filtre schvaľovania](../../../src/main/java/sk/iway/iwcm/branch/BranchMergeService.java#L651), [Oracle a `NULL`](https://docs.oracle.com/en/database/oracle/oracle-database/19/sqlrf/Nulls.html), [Oracle LOB](https://docs.oracle.com/en/database/oracle/oracle-database/19/adlob/SQL-semantics-and-LOBs.html).
- Pre strom použiť Oracle hierarchický dotaz s detekciou cyklu alebo spoločný algoritmus s rovnakým rozsahom domény. Oracle 19c povoľuje najviac 1 000 výrazov v jednom `IN`. Náhľad dnes niektoré zoznamy skladá priamo. Vo výbere poslednej histórie treba oddeliť výber a bezpečné zamknutie riadka, pretože `FETCH` sa s `FOR UPDATE` v Oracle 19c nedá kombinovať. [Zoznamy v náhľade](../../../src/main/java/sk/iway/iwcm/branch/BranchSql.java#L29), [výber histórie](../../../src/main/java/sk/iway/iwcm/branch/BranchPublishRows.java#L129), [Oracle `IN`](https://docs.oracle.com/en/database/oracle/oracle-database/19/sqlrf/IN-Condition.html), [Oracle `SELECT`](https://docs.oracle.com/en/database/oracle/oracle-database/19/sqlrf/SELECT.html).

## Podmienky na deklarovanie podpory

1. Na skutočnom serveri overiť čistú inštaláciu, aktualizáciu existujúcej schémy, opakovaný štart, jednu registráciu cronu a funkčný LIVE pri vypnutých balíkoch.
2. Otvoriť a uložiť balík cez bežné JPA/JDBC cesty. Pri súbežnom LIVE ukladaní overiť unikátne a trvalé ID stránky, priečinka a média, ich zachovanie aj po reštarte DB a neprítomnosť rezervácií vo verejnom čítaní.
3. Skontrolovať náhľad stromu, stránok, menu, Noviniek a médií vrátane výberu verzie, presunu, koša, perex a atribútového filtrovania, radenia i stránkovania. Použiť aj veľký HTML obsah, Unicode, `NULL` a väčší balík.
4. Overiť ručné, plánované a súbežne vyvolané publikovanie. Po chybe pred commitom očakávať spoločný rollback, po chybe po commite pokračovanie bez duplicitnej histórie či súborov. Overiť výsledok SQL vyhľadávania aj Lucene.
