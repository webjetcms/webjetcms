# Publikačné balíky v šablónach a komponentoch

Náhľad vykresľuje zvolený výsledok LIVE/WORK v existujúcom layoute. Samotná URL gateway nezmení priame zákaznícke SQL alebo JPA na pracovné čítanie. Pred použitím komponentu v pracovnej verzii overte jeho čítanie, odkazy, súbory, cache a vedľajšie účinky. Konkrétny inventár je v [návode správcu](../../../admin/setup/publishing-packages.md).

## Čítanie a kontext

`BranchFilter` overí prihláseného administrátora, doménu a výber; komponent používa už overený request. `BranchContexts.current(request)` rozlišuje `LIVE`, `ADMIN` a `PREVIEW`. Konštrukcia kontextu zo samotného query parametra nie je autorizácia. ADMIN uchováva WORK, PREVIEW používa spoločné rozhodnutia výsledku; nevyriešený konflikt je označený pracovný predpoklad, zastarané rozhodnutie sa odmietne.

Pre jednoduché čítanie slúži `sk.iway.iwcm.branch.BranchReadService`: `getDoc`, `getGroup`, `documents`, `groups`, `docIdFromUrl`, `docLink`. Adaptované bežné `DocDB`, `GroupsDB`, `MediaDB` a `DocDB.getDocLink` používajú účinné dáta. Odkazy skladajte existujúcim API, ponechajte logické URL v uloženom obsahu. Fyzické súkromné cesty nepatria do HTML ani do databázových odkazov.

Pre SQL zoznam dokumentov je určený `BranchSql.documentSource("d")`. Jeho `Fragment.sql()` tvorí účinnú reláciu a `bind(statement, firstIndex)` naviaže argumenty a vráti ďalší index. Na túto reláciu aplikujte doménové/prístupové filtre, count, radenie a paging. Dodatočná výmena objektov až po `LIMIT` dá nesprávny počet aj poradie. JPA repository bez adaptácie stále číta LIVE; nejde o automatický filter všetkých entít.

Výsledky pracovného requestu neukladajte do zdieľanej LIVE cache. Kontext sa nesmie prenášať singletonom ani ThreadLocal mimo existujúceho request lifecycle. Technický LIVE scope cez `BranchContexts.live(...)` použite len po vlastnej autorizácii operácie a vždy v `try-with-resources`; nemení výber session.

## Správa pracovných verzií a domény

`BranchRepository` rozširuje `DomainIdRepository` a `BranchEntity` ukladá `domain_id`. DataTables tak používa štandardné filtrovanie pri zapnutom oddelení údajov domén a kontrolu ID domény odoslaného editorom. Načítanie konkrétneho záznamu zabezpečuje zdedené `getOneItem(...)` bez vlastného override. Vytvorenie nastavuje ID domény na serveri cez `CloudToolsForCore.getDomainId()`.

Podľa potvrdeného Q20 je `enableStaticFilesExternalDir=true` podmienkou funkcie. Oddelenie balíkov používa iba `domainId`; varianta so spoločným ID `1` sa nepodporuje. Názov domény zostáva potrebný na zobrazenie a URL náhľadu, nie ako druhý kľúč vlastníctva. Session výber uchováva `domainId`; API očakáva `expectedDomainId`, hlavička `X-WebJET-Branch-Domain` a parameter vnoreného editora `branchDomain` prenášajú číselné ID. Náhľad a cron načítajú `domain_id` z balíka a cez `GroupsDB` odvodia routovaciu doménu. Mapa doménových ID zostáva z LIVE aj po odstránení koreňa vo WORK. Súbory sa mapujú existujúcim `Tools.getRealPath()` v overenom doménovom kontexte.

Pri ukladaní stránok a priečinkov platí rovnaká doménová kontrola ako pri načítaní pracovného stromu: prázdna hodnota `domain_name` alebo `default` neoznačuje cudziu doménu. Explicitná cudzia doména, práva používateľa a zákaz úprav System obsahu sa kontrolujú naďalej. Zamietnuté úpravy vracajú editoru lokalizovaný dôvod.

## JPA a transakčné úložisko

`BranchAccess.isEnabled()` spája `branchesEnabled` a `enableStaticFilesExternalDir` pre administráciu, filter, cron aj prísnu DB izoláciu. Ak chýba ktorékoľvek nastavenie, pracovné verzie sú vypnuté; `requireUser()` ich odmietne stavom 404 a DBPool zachová bežné správanie izolácie.

`branchStorageRoot` má predvolenú hodnotu `/WEB-INF/branches`. `BranchReadiness.storageRoot()` ju preloží cez `Tools.getRealPath()`; rovnaký resolver používajú pracovné súbory, BASE kópie, thumbnail cache aj publikovanie. Prázdny override použije predvolenú cestu, ktorá sa automaticky vytvorí pri kontrole pripravenosti. Vlastný absolútny adresár musí existovať. Kanonická kontrola povoľuje súkromné podadresáre `/WEB-INF` alebo úložisko mimo webrootu a odmieta verejné cesty; predvolená cesta musí zostať v chránenom `/WEB-INF` aj po rozlíšení symlinkov.

`BranchRestController` spája správu DataTable, zoznam prepínača, výber kontextu a náhľad. Používa zdedené `getOneItem`, `insertItem` a `editItem` z `DatatableRestControllerV2`. `DomainIdRepository` zabezpečuje doménové načítanie a Editor nastavuje/kontroluje `domainId`. `beforeSave` inicializuje nový balík, kontroluje pripravenosť pri vytvorení a nastavuje autora a čas úpravy. Názov validujú anotácie entity; farba má iba limit 16 znakov podľa DB stĺpca, bez validácie členstva v palete UI. Automatický audit poskytuje `AuditEntityListener`.

Entita používa bežné JPA mapovanie bez obmedzení `insertable=false` a `updatable=false`. Pri úprave metadát štandardný DataTable merge zachová hodnoty polí označených `hiddenEditor=true`. Vytváranie používa výlučne DataTable Editor na `/admin/rest/branches/editor`; `beforeSave` nastaví stav DRAFT, revíziu 0 a vyprázdni plánovanie, priebeh a chybu publikovania. Samostatný create endpoint ani `BranchService.create` sa nepoužívajú. `BranchService` zabezpečuje metadátové čítanie a publikačné prechody; samostatná metóda `updateMetadata` a jej zámkový query už nie sú potrebné. Publikačné prechody naďalej používajú podmienené JPQL/SQL operácie s kontrolou stavu a revízie.

`BranchService` nemá spoločnú transakciu na úrovni triedy; jednotlivé aktualizačné JPQL metódy v `BranchRepository` majú vlastné `@Transactional`. Metadáta načítava štandardné `GET /admin/rest/branches/{id}`; report porovnania a publikovania používa `GET /admin/rest/branches/{id}/progress`.

HTML porovnania jednej stránky načítava `GET /admin/rest/branches/{id}/page-content`. `BranchMergeService.pageVersions(...)` overí doménu a existujúce oprávnenia požadovanej položky vrátane pôvodného a cieľového priečinka. Načíta jej skutočné LIVE/WORK odtlačky a kontrolér ich porovná s otvoreným porovnaním. Táto požiadavka nespúšťa kompletnú prípravu balíka ani kontroly publikovania ostatných položiek. Výber surovej verzie, kontrola zastaraných odtlačkov, zvýraznenie zmien a sandbox vykresleného HTML zostávajú súčasťou tejto cesty. Kompletné kontroly pred publikovaním vykonáva pôvodný report a preflight.

DataTable mazanie deleguje na doménovo obmedzené `BranchService.delete`. Zmazanie entity cez JPA odstráni aj `branch_documents`, `branch_groups`, `branch_media` a `branch_files` cez FK s `ON DELETE CASCADE`. `BranchFiles.deleteBranch` odstráni súkromný adresár verzie aj jej thumbnail cache. Mazanie je nezávislé od behu publishera a neobmedzuje ho stav verzie. Publikovanie vykonáva pevná úloha `BranchScheduler` postupne vo svojom cron vlákne; súbežný beh tej istej úlohy na jednej inštancii sa preskočí. Súbežné zmazanie môže publisher ukončiť chybou; už vykonané LIVE zápisy sa nevracajú späť. Samotné mazanie nezasahuje do LIVE obsahu ani histórie. `afterDelete` vyčistí aktívny session výber a použije štandardné presmerovanie DataTable na obnovenie stránky. Import a export sú v lište skryté.

Rovnako ako `GroupPublisher` načítava záznamy z `groups_scheduler`, jediný `BranchScheduler` načítava kandidátov z `branches`. Predvolene beží každých päť minút. Pre splatné balíky `SCHEDULED` znovu overí podklady, transakčne prevezme stav a zavolá `BranchPublishService.run` priamo v cron vlákne. Publisher nemá vlastný executor a pre jednotlivé balíky nevznikajú záznamy v `crontab`.

Ručné publikovanie a pokračovanie používajú `BranchMergeService.enqueue`: v jednej transakcii uložia nemenný plán, stav `MERGING` a autora požiadavky do `publish_requested_by`. Najbližší cron beh atómovo spotrebuje požiadavku podľa ID, revízie a autora a publikuje balík. Úprava názvu alebo farby nezmení uloženého publikujúceho. Čakajúca požiadavka blokuje opakované pokračovanie a zostáva uložená aj po reštarte. `MERGING` bez požiadavky ani `MERGE_FAILED` sa automaticky neopakujú; pád po prevzatí vyžaduje nové overenie a pokračovanie z checkpointov.

Náhľad načítava doménu balíka cez JPA. Scheduler používa repository pri výbere splatných balíkov a označení potreby zásahu. Dokončenie a chyba publishera používajú podmienené JPQL aktualizácie s kontrolou stavu, pri scheduleri aj revízie a termínu. Definície kategórií médií sa čítajú existujúcim JPA repozitárom. `BranchMediaRows` načíta obsah média aj členstvo v kategóriách jedným cieleným JDBC dotazom. Odtlačky a výber LIVE/WORK používajú pôvodné databázové hodnoty; `XssAttributeConverter` sa aplikuje až pri vytvorení objektu pre zobrazenie. JPA escapovanie HTML znakov tak nevytvára falošnú súbežnú zmenu. Binárne porovnanie používa `BranchFileRepository` na načítanie súkromnej súborovej identity.

Detail média používa dotaz podľa ID a domény, vnorený zoznam podľa vlastníka a domény. Celý zoznam domény sa načítava iba pre prehľad všetkých médií. `BranchMedia` zdieľa načítaný detail a definície kategórií len v rámci aktuálneho `BranchView`; opakovaná kontrola oprávnení tak nečíta médiá znova. Volajúci dostáva nový objekt média, aby rozpracovaná úprava nezmenila podklad kontroly. Obnovenie pohľadu po zápise alebo zmena kontextu zahodí aj túto cache. `GroupsDB.getRootGroups()` vracia zoradené kópie koreňov z existujúcej LIVE cache, aby výber a overovanie domén nepotrebovali ďalší SQL dotaz.

Kontrola výsledku uloženia v `BranchEditor.validateResult(...)` používa už načítané metadáta jednotlivých `BranchView` cez `metadataDocuments()` a `metadataDocument(id)`. Porovnáva pôvodný a nový pohľad bez SQL dotazov v slučke pre každú stránku, referenciu či hlavnú stránku priečinka. Pôvodné chyby staršieho obsahu naďalej toleruje, ale nové kolízie URL, odkazy na zmazané stránky a neplatné hlavné stránky odmieta. Metadáta patria konkrétnemu pohľadu pred zápisom alebo po ňom a nezdieľajú sa medzi požiadavkami. Výsledný pohľad sa znova obnoví iba pri dodatočnom zápise hlavnej stránky priečinka.

Natívny JDBC zostáva v rezervácii existujúcich produkčných ID, v klasifikovaných WORK/LIVE zápisoch a checkpointoch, ktoré musia zdieľať jednu transakciu a spojenie. Rovnako zostáva v účinných SQL reláciách stránok a Noviniek a pri kontrole fyzickej schémy, engine a DB oprávnení. Tieto transakcie nerozdeľujte volaním nezávislého JPA repository uprostred zápisu.

Obsahové tabuľky, histórie, mediálne väzby a branch tabuľky používajú InnoDB. Migrácia `Publishing branches` konvertuje pôvodné tabuľky s iným enginom; existujúce InnoDB tabuľky neprebudováva. `pkey_generator` nepatrí do spoločného rollbacku obsahu a môže zostať na MyISAM. `PkeyGenerator.getNextValueAsLongStrict` prideľuje ID z rovnakých rozsahov ako pôvodné API samostatným atómovým zápisom; chyba následného WORK insertu číslo spotrebuje. Chýbajúci generátor alebo jeho nesprávne mapovanie sa naďalej odmietajú.

## Overené aplikácie

Dialóg **Úpravy v hlavnej verzii** sa zobrazuje pri otvorení nepodporovanej obrazovky rozpoznanej cez `MenuService.getPerms(...)`. Používa tak existujúce mapovanie položiek a podmenu vrátane starých a nových adries; zahŕňa aj editor obrázkov registrovaný v oprávneniach. Vlastnosti súborového priečinka (`/admin/v9/files/folder_prop/`) majú samostatnú výnimku, pretože upravujú zdieľané metadáta a nemajú vlastnú položku menu.

Samotný prefix `/admin/` ani prípona `.jsp` neznamenajú samostatnú obrazovku. Pomocné GET/HEAD požiadavky mimo tohto mapovania sa načítajú bez dialógu a zachovajú overený kontext volajúcej obrazovky. Celý `/admin/skins/webjet8/ckeditor/` je dostupný v pracovnej verzii vrátane dynamických skriptov, napríklad `fck_dialog_common.jsp`. Aj `/admin/scripts/combine.jsp` môže načítať vlastnú nakonfigurovanú sadu skriptov alebo štýlov. Zápisové operácie naďalej vyžadujú podporovaný branch vstup; sprístupnenie pomocnej URL nepovoľuje nepodporovaný zápis do hlavnej verzie.

CKEditor zobrazuje pracovné obrázky cez `/admin/webpages/branch-preview/{id}/...`, ale pole URL v dialógu a výsledné HTML používajú logickú cestu `/images/...` alebo `/thumb/images/...`. `configureBranchImageUrl(...)` upravuje natívny URL field dialógu: načítanie náhľadu a rozmerov používa pracovnú URL, potvrdenie ponechá logickú hodnotu v `data-cke-saved-src` a nastaví pracovnú URL iba do zobrazovaného `src`. Toto platí aj pri priamom výbere zo servera bez prepnutia režimu editora. Existujúce HTML filtre pri serializácii odstránia interný prefix. Nový súbor dostupný iba v pracovnej verzii nemá verejnú URL až do publikovania balíka.

Verejné volania z `/components`, `/apps` a `/templates` sa spracúvajú bežne bez prepínania pracovnej verzie. Platí to aj pre dynamické CSS/JS, napríklad `/components/_common/combine.jsp` a `page_functions.js.jsp`, a verejné AJAX požiadavky. V `/components` a `/apps` sa za administráciu považuje iba cesta obsahujúca `admin`, napríklad `/apps/news/admin/` alebo `admin_save.jsp`. Ich pôvodné kontroly prístupu sa naďalej vykonajú. Náhľad cez gateway naďalej číta pracovné stránky a súbory a odmieta zápisové metódy; verejná adresa samotného komponentu nie je náhradou za gateway.

Obrázkové náhľady v gateway spracúva existujúci `ThumbServlet` vrátane jeho parametrov `w`, `h`, režimov `ip`, farby `c`, kvality `q`, `noip` a rozmerov zakódovaných v názve súboru. Používajú vybrané pracovné alebo hlavné bajty a súkromnú cache oddelenú podľa verzie, obsahu, galériového výrezu a parametrov. Pri nezmenenom obrázku sa zachová galériový originál aj výrez; pracovná náhrada používa vlastné bajty. Zmazaný pracovný obrázok sa nenahradí hlavným ani starou miniatúrou. Náhľad nemení záznamy galérie a neposiela pracovné obrázky na verejný uzol na generovanie miniatúr.

Náhľady vložených aplikácií v CKEditore vykresľuje štandardný `WriteTag`, rovnako ako v hlavnej verzii; nemajú osobitný branch whitelist rendererov. Funguje tak aj zobrazenie existujúceho kontaktného formulára. Editory parametrov aplikácií používajú štandardnú AppStore registráciu a existujúce oprávnenia bez osobitného zoznamu povolených tried pre pracovné verzie. Parametre sa ukladajú do include kódu stránky. Správa zdieľaných dát aplikácie naďalej používa vlastné endpointy a ich kontroly zápisu; samotné otvorenie editora parametrov jej nedáva výnimku.

Synchronizačné polia stránky sa neposielajú cez editorové JSON API (`@JsonIgnore`). Branch zápis ich ponecháva zo serverového riadka a neporovnáva ich s predvolenými hodnotami prijatého formulára. Bežná úprava textu preto funguje aj pri existujúcom `syncStatus=1`; individuálne dátumy publikovania sa naďalej nemenia.

`MenuULLI` zachováva existujúce parametre vrátane koreňa, hĺbky, tried a `onlySetVariables`; číta účinný strom. `NewsActionBean` vykonáva filter/count/paging nad účinnou SQL množinou. Používa existujúce perex kategórie, štandardné criteria a jeden `previewAt` na request. Vlastné `ResultCriteria` a `contextClasses` v preview vyžadujú adaptér. Zdieľané funkcie `FileTools.getFileIcon` a `ForumDB.isActive` sú dostupné cez čítacie adaptéry; nemenia súbory ani diskusie hlavnej verzie. Dátum autora/uloženia nie je čas publikovania balíka.

Testujte skutočný JSP/Velocity render, preklik cez menu a Novinky, dve vetvy/LIVE a zahriatu cache. Pred merge zachyťte výsledok s rovnakou šablónou, časom a identitou a porovnajte ho s LIVE po merge. Normalizovať možno hostiteľa, prefix gateway a lištu, obsahové rozdiely sa nesmú zakryť. P08 dopĺňa aj anonymný verejný výsledok pre obsah bez prístupového obmedzenia.

## Zápisy a rozšírenia

Bežné ukladanie stránok musí ísť cez `EditorFacade` a branch editor, upload cez existujúce adaptované vstupy. Priamy SQL/JPA zápis v komponente obíde izoláciu, práva a históriu. Náhľad nie je sandbox pre ľubovoľné JSP: formulárové objednávky, emaily a zákaznícke zápisy sa v ňom nepovoľujú. Pred publikovaním sa odmietajú aj nepodporované fulltext hooky a multigroup zápisy.

Jadro má štyri typy `DOCUMENT`, `GROUP`, `MEDIA`, `FILE`, spoločný `BranchChange`/`BranchDecision`, prípravu a priebeh. Každý typ má jediné WORK úložisko; súborové bajty sa nepublikujú v DB transakcii. Neznámy typ REST odmietne, nesmie sa preskočiť. Nový modul potrebuje vlastný dohodnutý kontrakt a testy; banner/galéria ani generický register/JSON storage nie sú súčasťou P08.
